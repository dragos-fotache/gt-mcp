## Binding / roots / envelope rules QA will assert literally

- Pre-auth skeleton: `provisionProfile` creates origin-bound `accountUuid=null, sessionGeneration=0`, supplied unused `profileGenerationId`; initial vault/operations payloads are empty byte arrays (not T09 JSON). `bindAccount` one-way null→trusted UUID only: atomically installs `replacementVaultBytes`, rebinds/re-encrypts metadata, sets generation 1; rebinding a bound profile → `binding_mismatch` even to the same UUID. `advanceSessionGeneration` requires bound profile, +1 exactly (overflow → `resource_exhausted`), atomically commits `replacementVaultBytes` with new generation/fence; operations bytes stay exactly identical; returns new frozen binding; all old-capture methods except `close` → `generation_mismatch`; caller closes and re-opens with the new binding. Binding getter stays the original frozen capture after transition. Double `close` succeeds; methods after close → `not_owner`.
- Roots: separate, disjoint, single-profile `profileRoot` + `anchorRoot`; neither contains the other; aliases/symlinks/same-root rejected. Layout fixed: `profileRoot/vault.bin`, `profileRoot/operations.bin`, `anchorRoot/owner.lock` (lock lives in anchorRoot), `anchorRoot/anchor.bin`, `anchorRoot/INCOMPLETE`. Roots 0700, files 0600, euid-owned; no group/other, links, nonregular store/anchor/lock files, nlink>1; unsafe existing roots/files → reject, no chmod repair. Ancestor assumptions: trusted root-owned or euid-owned traversal, sticky system-temp parent allowed for fixtures; same-UID active adversaries, ptrace, intra-syscall ancestor swaps excluded; O_NOFOLLOW+lstat not claimed race-free. State + stable lock descriptor identity revalidated before each call/commit; no unlink/replacement by implementation or supported restores. Supported restores copy data-root store files only with current anchor root + key intact; transfers/restores replacing the anchor, NFS/overlay/FAT, ext-magic-alone durability claims, and tmpfs-as-production are unsupported/fail-closed (tmpfs only via diagnostic facility).
- Envelope: magic `GTMS2` (5 B), version u16BE=1, family u8 (vault=1, operations=2, anchor=3), random 256-bit salt, random 96-bit nonce, plaintextLength u64BE, ciphertext, GCM tag 128 b; header 60 B; total exactly 76+plaintextLength. Length/overflow/version/family gates precede allocation; magic/shape/auth → `store_corrupt`; recognized unknown version → `store_version_unsupported`. Sensitive metadata encrypted or AAD only, never cleartext header/diagnostics. HKDF-SHA256 32 B record key from immutable master + header salt, info `gymtracka-storage-v1:<family>`; data-store AAD = header bytes + UTF-8 JSON `[origin, accountUuid, profileGenerationId]` (exact order, no whitespace); anchor AAD = header bytes + UTF-8 `profileGenerationId` (recoverable before comparing decrypted binding; never caller-mutable account/session). Full decrypted binding validated before exposing data. Per-envelope salt+nonce = probabilistic resistance only; no impossibility claim; no acknowledged-sequence-bounds-unacknowledged-attempts claim; CSPRNG/HKDF/AEAD justification + owned-buffer scrub on close live in the ADR (no whole-V8-erasure claim).
- Anchor payload: versioned record `{ phase PROVISIONING|PREPARED|COMMITTED, seq UInt64-decimal-string, current binding, SHA-256 of entire encrypted vault/operation files, root identity commitments, lock dev/ino }`; PREPARED additionally retains target binding/digests/seq for diagnosis only. COMMITTED admits exactly current digests+binding: missing file → `store_missing`; digest mismatch → `fence_mismatch`; bad format per envelope rules; missing anchor → `anchor_missing`; PROVISIONING/INCOMPLETE → `incomplete_provision`; PREPARED → `commit_ambiguous` regardless of file match. No previous-manifest fallback; no auto roll-forward/discard/reconciliation.
- Argument/call discipline: exact own-data shapes, no unknown fields/coercion/accessor-invocation/cycles; byte views must be actual Uint8Array/Buffer, rejecting SharedArrayBuffer-backed, detached/invalid, array coercion; UUIDs canonical lowercase; generations nonnegative safe ints; canonical configured HTTPS origin (no credentials/path/query/fragment); roots absolute, symlink-component-free, non-overlapping/safe; bus address single Unix FS path (+optional valid guid), never tcp/abstract/unixexec/multi-fallback, no ambient discovery. Each call validates/copies byte args before queueing; reads/digests return independent copies (copy-semantics + independence observable). All calls serialize incl. reads/close/generation; no overlap across two handles/processes. Empty `StoreUpdate` rejects; zero-length store payloads valid. No implicit startup IO.

## Critical-case matrix (exact codes / observables)

All fixtures synthetic (placeholder origin e.g. `https://storage-qa.example.invalid`, synthetic UUIDs, disposable temp roots, synthetic payload canaries). Each row: setup → action → required observable.

1. **Current-only anchor; previous-ACK rejection:** COMMITTED seq N acknowledged → snapshot encrypted stores+anchor → COMMITTED seq N+1 acknowledged → restore the seq-N pair under the same binding → `openProfile`/`read*/commit` → `fence_mismatch` (never success/fallback). Restoring the immediately-previous acknowledged state is a required negative test.
2. **PREPARED always unavailable:** arm `commit.anchor.prepared` (+ `commit.before.prepare` variant) → `commit` → `commit_ambiguous`; fence handle (no further usable reads/writes until close + explicit reopen); reopen admits only authenticated COMMITTED current manifest. No previous-manifest acceptance, no roll-forward.
3. **Missing entries vs anchor:** with current anchor intact, delete `vault.bin`, `operations.bin`, `anchor.bin` each singly → `store_missing` / `store_missing` / `anchor_missing`; no phantom/empty-store synthesis; unused temps never count as stores; T09 reservations never silently dropped.
4. **Partial provisioning:** kill/throw at each of `provision.marker.durable, provision.key.stored, provision.stores.durable, provision.anchor.committed, provision.marker.removed` → residual state always fails closed (`already_provisioned` / `incomplete_provision` / key errors as applicable); P-retry and open never yield a usable apparently-fresh profile; failed generation never reused/regenerated on open/recovery; INCOMPLETE + PROVISIONING-anchor + key-vs-anchor ordering (durable marker or existing key after every first side effect) observable via file inventory. Fence-before-state-complete never implies usability.
5. **Post-rename ambiguity:** faults at `commit.vault.renamed/synced`, `commit.operations.renamed/synced`, `commit.anchor.committed/synced`, `commit.reply`, and `fs.*` equivalents after rename began → `commit_ambiguous` + permanently fenced handle; never a promise that old files are untouched; uncertain evidence preserved; no reset/reconciliation method. Faults strictly before any PREPARED attempt → `io_failure` with old COMMITTED state still usable. Kill after fully durable commit+reply boundary → fresh explicit open of exact current state (never prior manifest); completed provision with lost reply is a reserved generation, not an incomplete profile.
6. **Master-only key custody:** Secret Service holds only the immutable 256-bit master per profile-generation; mutable anchor is the separately file+dir-flushed filesystem record. Key loss → `key_not_found` before any new write; no reconstruction/replacement on open (provision requires zero prior reserved items; creates one immutable 32 B secret + encrypted-session read-back + uniqueness check). Missing dir-fsync on the key side cannot roll the mutable anchor back. Key states: `missing→key_not_found`, `locked→key_locked` (no Unlock/Prompt invocation, no prompt), `ambiguous (0→key_not_found; >1→key_ambiguous)`, `unavailable→key_unavailable`/`provider_failure` per observed code family, timeouts bound the whole call. No CreateCollection/Unlock/Prompt in production; ephemeral session collections are not production facilities; attributes are reserved version/profile-generation/master-key only + fixed non-identifying label (no account/origin/resource/body attributes); exact session algorithm `dh-ietf1024-sha256-aes128-cbc-pkcs7`; raw framing over validated Unix socket only (no ambient/TCP/unixexec/introspection/autostart/plaintext session); direct/manual bounded Hello; socket/session closed on timeout/close.
7. **Atomic vault+generation, exact ops bytes:** `bindAccount` and `advanceSessionGeneration` each commit replacement vault + new binding/fence atomically; `readOperationStoreBytes` before/after → byte-identical; no split acknowledgments leaving old credentials usable after a fenced report; overflow advance → `resource_exhausted`.
8. **Pre-auth + old-capture invalidation:** pre-auth skeleton usable for protecting pre-dispatch exchange evidence (empty initial payloads); one-way bind semantics per above; after any transition, old-handle reads/commits/digest (except `close`) → `generation_mismatch`; binding getter still returns the frozen original. Different origin/account never inherits old IDs/bytes; same-Google-new-UUID is a distinct binding (shared-contract rule, storage enforces mismatch).
9. **Async holder digest:** `keyedIntentDigest` async through holder; derivation HKDF-SHA256(empty salt, `gymtracka-digest-v1\0origin\0accountUuid\0profileGenerationId`) → HMAC-SHA256(`DIGEST_KEY_VERSION\0` + input bytes); stable across session generations (no session-generation in KDF); null-account call → `binding_mismatch`; no input normalization, no resource-ID allocation, no key returned; keys never rotate/rebind for retained receipts (T03 material retained by T09).
10. **Lease holder / no unlocked IO:** parent opens/creates nonsecret lock file (open-existing for open), validates inode/type/ownership/mode, passes fd as child fd3, closes parent copy; spawns `flock --no-fork --exclusive --nonblock --conflict-exit-code 73 /proc/self/fd/3 <node> <holder>` (direct argv, no shell/`--command`/`--close`/addons); holder starts only with private IPC (fd4) AND fdinfo-verified matching lease, else fails closed before protected IO; holder alone decrypts/reads/writes/contacts key facility/holds keys; parent marshals copies only; conflicting inode/root identity rejected even for a newly-created lock file; holder exit/IPC loss permanently fences parent handle + outstanding replies; parent death closes IPC and the holder settles/fences in-flight commit then exits with kernel ownership held until exit (no heartbeat/time/PID guessing, no abandoned-worker re-grant — deadline failure terminates the worker first); child stderr/native errors drained, never echoed/retained/included (sanitized codes only). Observables: two processes/handles never overlap protected IO; kill-holder/parent-death/inode-replacement cases serialize or fail (`locked_by_other_owner` / fenced / `commit_ambiguous` as applicable); `holderPid` used only for the fixture's own diagnostic worker (never production owner guessing). Node-has-no-flock-API and no-fork-vs-fork topology per preflight stand.
11. **No production test flags:** production factories reject unknown test/provider fields; synthetic `setKeyState`/armed faults exist only as durable controls under the issued facility root (`controls.json`); `cleanup` removes only its issued root after holders close (contention → `locked_by_other_owner`, never PID/time killing or private-path deletion); no env/CLI/config activation path; same persistence/lease logic under a separate diagnostic worker; `attachStorageTestFacility` issuance/link checks enforced at runtime.
12. **Capacity is operational:** over-`MAX_STORE_BYTES` plaintext (either store) → `resource_exhausted` before commit; no truncation/eviction/TTL/retirement; never surfaced as `invalid_argument` or silent backend no-op; public constant checkable by caller; T09-side headroom reservation is a T09 obligation (QA notes the contract effect; no T03 schema/name/count cap changed or tested here).
13. **Tamper/swap/unsafe/version:** ciphertext bit-flip, vault↔operations blob swap, metadata-block swap, header family/length/version abuse → `store_corrupt` (auth) or `store_version_unsupported` (recognized unknown version) or `fence_mismatch` (digest-vs-anchor); cross-store key does not open sibling; symlink/unsafe-mode/foreign-owner/nonregular/nlink>1 roots or files → `invalid_argument`/`io_failure` family per spec mapping with no repair; canary grep-absence + `stat` modes + no-plaintext-binding-metadata asserted.
14. **Exact/copy bytes + envelope math:** round-trips (empty valid, single-byte, all-zero, 0x00–0xFF, large within budget) identical after close/reopen; caller-buffer mutation post-commit and returned-buffer mutation pre-reread do not affect stored image; total size exactly 76+plaintextLength; over-length/overflow gates precede allocation.
15. **Sanitized errors/imports:** every failure above surfaces exactly `Storage failure: <code>.` (+ exact name/stack, immutable code, no extra fields); captured stdout/stderr/IPC/error bytes contain no canary, UUID, path, key, or native message; imports of production/holder/diagnostic artifacts inert under arbitrary argv with no stdio except internal worker IPC; direct holder-without-lease → sanitized failure only.
16. **Regressions on frozen relay only:** foundation 100/100 exact inert bytes/exits + T03 221/221 boundaries unchanged; no whole-suite, no parked-T02, no mock-only OS certification; skips stay failures.
