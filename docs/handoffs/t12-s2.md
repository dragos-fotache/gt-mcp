## Delivered controls and boundary

```text
node dist/cli/main.js profile-remove --config <absolute normalized config path> --confirm
node dist/cli/main.js setup --config <absolute normalized config path> --reconcile --confirm
node dist/cli/main.js recover --config <absolute normalized config path>
```

Stop the stdio owner first; no takeover. Warnings/confirmation are trusted local
intent, not routine approval. No backend-auth requirement for local removal, no
HTTP/DELETE, no model-facing lifecycle tools. Errors/output stay sanitized and
stderr-only. Before preparation cancellation prevents action; afterward signals
wait for durable work/publication/release, never claiming rollback.

`dist/lifecycle/index` adds removeLoginProfile/reconcileLoginProfile. Production
storage sessions add removeProfile/verifyRemovedProfile; the separate inert
`dist/storage/lifecycle` exports resumeProfileRemoval/provisionReconciledProfile.
All destructive/provisioning work uses the actual existing lease holder. Retain
exact root/lock commitments. Do not unlink lock/fences/roots or delete arbitrary
provider items to make setup pass.

Removal durably records pending external intent before erasing exact manifested
owned encrypted files and the unique original matching provider key. Survives
holder death before/after files/key/complete acknowledgement without old-key
access. Replacements/links/root changes, stale/corrupt records and unavailable/
ambiguous/locked/replaced provider keys fail closed. Complete fence keeps only
credential-free generation/location commitments; descriptor becomes unbound,
matching abandoned metadata temps/pending receipt are erased. Other profiles survive.

Ordinary setup/login/open cannot reuse a removed generation. Only explicit
reconciled setup after remote reconciliation creates a distinct generation/key,
empty evidence and a strict metadata transition while retaining old fences.
Recovery verifies completed target plus old completed source fence, or unchanged
clean removed source; no old IDs or routine names are imported. Interrupted T04
INCOMPLETE/ambiguous provisioning stays fail-closed, requiring bounded review.
